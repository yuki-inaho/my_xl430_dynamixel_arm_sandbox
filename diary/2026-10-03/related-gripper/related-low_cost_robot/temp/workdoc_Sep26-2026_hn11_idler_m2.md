## 1. 作業目的

HN11-I101の代わりに使うアイドラ部品を設計し、確認可能なSTEP一式と、Ender-3 Proで同じ一式を6組同時に出力するG-codeを準備する。既存の試作形状・スライススクリプトはレビュー対象として扱い、未検証の寸法やレポートをそのまま製造承認に使わない。

* **目標1：** 支給資料と実物インターフェースを照合し、交換対象・固定方法・部品点数を確定する。
* **目標2：** 支給されたM2真鍮ヒートセットインサートに合う代替形状をパラメトリックに設計し、部品STEP・組立STEP・STL・部品表を作る。
* **目標3：** CAD形状、挿入方向、ねじ締結、回転すきま、印刷性を根拠付きで確認する。強度や寿命を未試験のまま保証しない。
* **目標4：** Ender-3 Pro用にクーポンと6組分の部品をスライスし、条件・オブジェクト数・G-codeを検査してSDカードへ保存する。
* **目標5：** 成果物と残件を再現可能な形で記録し、private情報や絶対パスをGit追跡対象へ混入させない。

### 1.1 ゴール要求分析

* **ユーザーの直観的・直截的な目的：** HN11-I101の代替部品を形にし、Ender-3用の材料設定で精密な試作を6組まとめて印刷できる状態にする。
* **明示要求：**
  * HN11-I101を置き換えるCAD STEPモデルを設計する。
  * インサートはユーザー提示品のESJNNK真鍮M2ヒートセットナット「M2×3 mm×3 mm」を使う。表記はM2ねじ、長さ3 mm、外径3 mmと読めるが、外径・ローレット最大径・適正下穴は未確認。
  * Ender-3系のPLA設定を使い、ノズル200°C、流量100%にする。なめらかさを優先し、積層厚は0.12 mmを初期候補とする。ベッド温度等は実プリンタープリセットを確認して記録する。
  * 完成した一式を6組、最終プレート1枚に配置する。インサート穴の確認用クーポンも作る。
  * 今回Codexが行う範囲は本書と会話JSONの作成まで。CAD確定・スライス・SD書込みは後続エージェントが実施する。
* **暗黙制約：**
  * CAD環境は skills/cad-reverse-parametric/ のuvプロジェクト。ルートとCADサブプロジェクトに pyproject.toml / uv.lock がある。justfile はリポジトリに存在しない（2026-09-26確認済み）。コマンドはuvで統一する。
  * M3 RevA資料は純正HN11を残す変換アダプター案であり、純正品の代替品としてそのまま使わない。RevAは外径4.6 mm想定のM3インサートを使うため、今回のM2インサート穴や寸法として流用しない。
  * 対象関節・リンクを現行アームと資料で特定する。異なるインターフェースを同一形状が満たすと仮定しない。
  * 熱圧入はクーポンで先に確認する。インサートの実寸・メーカー指定穴が確認できない場合、本体穴寸法を確定値と扱わない。
  * 生成物、セッションJSON、プリンタープリセットは temp/ 等ignore対象に置き、追跡対象へ個人情報・絶対パス・未許諾の参照STEPを入れない。commit/pushは今回の範囲外。
  * テストは対象CAD・スライス検証に絞る。全リポジトリ回帰suite完走は印刷準備のDoDにしない。
* **非ゴール：**
  * 実機取り付け、通電、ロボット運転、荷重・摩耗・寿命・安全率の認定。
  * 未提示のインサート寸法、締結トルク、モーターねじ深さを推定値で確定扱いすること。
  * K1C用G-code、複数プレートへの自動分割、現物の印刷開始。
  * 本書を作るCodexがCADを承認したりSDへ書き込むこと。
* **成功条件：**
  * 対象部位・一組あたりの部品数・締結方法・インサート実寸が証拠付きで記録される。
  * 再生成可能な部品STEP・配置付き組立STEP・STL・寸法付きクーポン・BOMが揃い、対象テストと形状検査を通る。
  * 200°C、流量比1.00、0.12 mm候補等の実設定が検査され、同一の完成セットが6組、最終プレート1枚にある。実寸未確認ならクーポン試験後の最終スライスである。
  * G-codeの機種互換性、温度、押出しリセット、ベッド内配置、オブジェクト数、スライサー成功結果を検査する。
  * SDへのコピー後にSHA-256が一致し、既存データを消していない。
  * 「試作印刷準備完了」と「機体へ組み込んで運転可能」を区別する。
* **リスクと前提：**
  * temp/hn11_replacement_20260926/ に既存試作がある。既存レポートは形状成立の一部を示すだけで、インサート適合・強度・寿命・組立適合を証明しない。
  * ドラフト仮定値ではインサート穴周囲の公称肉厚が約0.75 mm、穴底が約0.30 mm。薄肉のまま承認せず、形状変更か設計停止を判断する。
  * ドラフトREADMEは6組＋クーポンのG-codeを記載するが、2026-09-26 17:41 JSTの確認時点でslice/とG-codeは存在しなかった。READMEは出力の証拠ではない。
  * 元アームSTEP上でドラフト部品とBase:1に約390.8 mm³の交差が記録されている。ダミー形状由来と決めつけず、対象部分の組立関係を確認する。
  * 出品ページの表記が実測図や適正下穴を保証するとは限らない。実寸未確定ならクーポン試験まで試作寸法として明示する。

## 2. 作業内容

### フェーズ 1: 調査・要求確定 (見積: 0.5〜1.0h)

1. **支給資料と既存案の照合：** ChatGPT-HN11-I101部品調査.md、HN11_M3_RevA_Package.zip、Drawing、Work Instruction、会話整理JSONを読む。M3 RevAが純正品保持アダプターである点とM2置換要求を分ける。**SG-1 / TR-1〜TR-2**
2. **実インターフェースの確定：** temp/hn11_replacement_20260926/input/HN11.step と hardware/follower/step/arm.step を照合し、対象関節、原品の全ソリッド、中心軸、リンク穴、締結位置、ケーブル通路を記録する。既知のP03側φ10×3 mm、P04/P05側φ11×4 mmは再確認する（P03/P04/P05は前セッションの呼称で、M02肩=P03リンク、M03肘=P04リンク、M04手首=P05リンク。出典は temp/session_extracts/hn11_idler_session.transcript.md 末尾のR3リンク中心穴表。今回の置換対象関節はこの照合で確定する）。**SG-1 / TR-3**
3. **インサート・ねじ仕様の確認：** ESJNNK品の現物または寸法図で、M2ねじピッチ、全長、ローレット最大外径、推奨下穴、圧入方向を採寸する。モーター固定ねじや中心ねじと、インサートを使うリンク締結部を混同しない。**SG-1 / TR-2〜TR-3**
4. **ドラフト成果物の監査：** 既存build.py、slice_six_sets.py、README_ja.md、validation.jsonと実ファイルを突合する。0.75 mm側壁、0.30 mm底厚、Base:1交差、未生成slice出力、G-code検査式を調べる。**SG-1 / TR-4〜TR-5**

寸法や対象関節を確定できない場合、推定値を承認寸法へ昇格させない。適合はクーポンで確認し、モーターねじ種類・有効深さ・ねじ長さが不明なら締結部の判定を保留する。

### フェーズ 2: パラメトリック設計と実装 (見積: 1.0〜2.0h)

1. **テスト先行：** skills/cad-reverse-parametric/tests/test_hn11_replacement.py に、部品数、穴PCD/位置、材料残厚、STEP再読込、異常入力拒否のテストを追加し、実装前に主要テストが失敗することを確認する。**SG-2 / TR-2〜TR-4**
2. **仕様と形状生成：** skills/cad-reverse-parametric/studies/xl430_lowcost/intent/ と parts/ に単位・出典付きのパラメータを定義する。既存ドラフトを無条件に踏襲せず、インサート座・床厚・外周壁、ケーブル通路、回転面、保持部を再設計する。**SG-2 / TR-2〜TR-4**
3. **一式の出力：** 再生成スクリプトで部品STEP、配置付き組立STEP、印刷向きSTL、穴径比較クーポン、BOMを出力する。成果物はCADプロジェクトのprototype出力下またはignore対象tempに置き、元の第三者STEPを追跡対象へコピーしない。**SG-2 / TR-1、TR-4、TR-6**
4. **TDD通過：** 実装後にHN11専用テストを通し、実装前の失敗理由と実装後の結果を記録する。**SG-2 / TR-2〜TR-4**

**実装ゲート：** 妥当な材料厚、既存締結経路、回転支持を両立できなければ無理にSTL化しない。別案または設計保留とし、ユーザー判断が必要な点を提示する。

### フェーズ 3: CAD・スライス検証 (見積: 0.75〜1.5h)

1. 生成STEPを再読込し、ソリッド数・妥当性・外形・体積と、元部品を保持する箇所の形状・配置を照合する。**SG-3 / TR-3〜TR-4**
2. 対象関節の静止姿勢、リンク回転範囲、ねじ頭・工具・インサート進入経路、ケーブル通路を検査する。サンプル姿勢を連続掃引の保証と呼ばず、交差体積と最小距離を別々に記録する。**SG-3 / TR-3〜TR-4**
3. 実測インサート周辺の穴径を含むクーポンをEnder-3 Pro用PLAでスライスする。今回の作業ではプリンターを始動しない。クーポンを実際に印刷した場合の穴径・圧入方向・割れ/膨れ・ねじ通過の記録欄を用意し、実物試験前は未確認と明記する。**SG-4 / TR-2、TR-5**
4. 一組に必要な全印刷部品を決め、その完全なコピーを6組、最終プレート1枚に配置する。必要なら比較クーポンを1個追加し、ベッド・間隔・重なり・ブリムを確認する。**SG-4 / TR-5**
5. プリセット継承を解決し、ノズル初層/通常層200°C、流量比1.00、層高0.12 mm候補、ベッド温度を検査する。G-codeの温度、G28、G92 E0、オブジェクト数、M191/M600の有無、Orca成功結果を個別に照合する。**SG-4 / TR-5**
6. 層別プレビューで外壁・底面・サポート・ベッド接着を見て、推定時間・材料量・精密さに関わる設定を記録する。スライス成功を強度の証明としない。**SG-3〜SG-4 / TR-4〜TR-5**

コマンドはリポジトリルートから実行し、CADプロジェクトのuv環境を明示する。

~~~
rtk uv run --project skills/cad-reverse-parametric pytest -q skills/cad-reverse-parametric/tests/test_hn11_replacement.py
rtk uv run --project skills/cad-reverse-parametric python temp/hn11_replacement_20260926/build.py
rtk uv run --project skills/cad-reverse-parametric python temp/hn11_replacement_20260926/slice_six_sets.py
~~~

既存スライススクリプトのG-code検査は、既存 prepare_print_package.py の _validate_gcode と tests/test_print_package.py の形式に合わせ、空白・小数表記を含む実例で陽性/陰性テストする。実出力の生成前にREADMEやスクリプト内の成功表示を証跡にしない。

### フェーズ 4: SD保存と引き渡し (見積: 0.25h)

1. ボリュームラベルsd_card_3dでカードを再検出し、容量・マウント・書込み可否を確認する。見つからない、重複候補、書込み不可なら停止する。**SG-5 / TR-7**
2. ASCII短名の新規ファイルとしてクーポン用と6組用G-codeをコピーする。既存G-codeやEEPROM.DATを削除・上書きせず、sync後にSHA-256を照合する。**SG-5 / TR-6〜TR-7**
3. STEP/STL/G-codeの相対パス、条件、所要時間、コピー結果、クーポン結果、残件を記録し、「試作印刷可」「実機仮組み可」「運転可」を別々に判定する。**SG-3〜SG-5 / TR-4〜TR-7**

### フェーズ見積合計

調査からスライス検査まで約2.5〜4.75時間。クーポンの実印刷・インサート適合測定、必要な再設計時間は含まない。実寸または締結条件が得られない場合は見積を超える。

## 5. エラー時の対処

- **添付資料なし / STEP読み込み失敗：** ファイル名で再探索し、原品形状を推測再構築しない。入力ハッシュ、失敗、必要資料を記録する。
- **インサート実寸不明：** M2表記からローレット径を決めつけない。比較クーポンで穴ごとの圧入とねじ通過を確認し、それまでは寸法適合済みとしない。
- **ねじ種類/有効深さ不明：** モーターケースへ試し締めしない。滑らかなCAD穴からねじ長さを決めず、測定/公式仕様まで保留する。
- **薄肉・破損リスク：** 現行ドラフト寸法を無条件採用しない。座位置や断面を再設計し、材料厚を確保できなければ印刷承認を止める。
- **基準組立との干渉：** 元データの既存交差と新設計の交差を分け、材料交差体積・配置・運動範囲を調べる。
- **Orca失敗/検査器の曖昧さ：** プリセット継承、機種互換性、開始G-code、温度を切り分け、誤検出/見逃しの陽性・陰性テスト後に再実行する。
- **SD誤認/書込み失敗：** デバイス名だけで決めずラベル・容量・マウントを照合する。容量不足/I/O/ハッシュ異常時はカードを初期化せず停止する。
- **ライセンス不明：** 参照寸法の利用と元形状の再配布を分ける。許諾不明の原本を公開物へ含めない。
