# 責務と境界

`geometry.py` はCAD参照空間、順運動学、相似姿勢と解析的Jacobianだけを扱います。`observations.py` は入力・注釈分離、`optimize.py` はE/M反復と明示的な画像補助、`evaluate.py` は共通選定と採用後の検証、`render.py` は奥行き判定、`reporting.py` は可視化出力、`cli.py` は実行・再開・記録を担当します。

C++の`MomentFilter`は固定観測からのGaussianモーメント、`assemble_blocks`はリンク別7×7正規方程式と関節空間への写像のみを担当します。nanobindとC ABIは別アダプタで、数値アルゴリズムを二重実装しません。Python側が計算核の選択を明示し、欠けているnanobindをC ABIと偽装しません。

数値核と`KinematicChain`は配列契約で異なるリンク数・関節数を扱います。ただし本依頼の初期化・散布・CLI記録はR3の4可観測関節に特化しており、別ロボットへの適用にはその設定・初期化部分の変更も必要です。CAD配列を入れ替えるだけで任意のロボットへ対応するとは主張しません。入力形式・カメラ・描画・最適化を単一の巨大神クラスに集めていません。関節ごとの点Jacobianを全点×全自由度で集約する代わりに、C++内ではリンクの固定サイズ行列へ一度集約します。Pythonの画像補助Jacobianは独立した項で、元のGaussian処理を変更しません。

外部のpermutohedral実装とEigenは`third_party/`に隔離し、新規コードと区別します。必要以上の抽象基底クラス、依存注入フレームワーク、非剛体変形モジュールは追加しません。点形状、有限性、回転行列、正の尺度、関節添字、ネイティブ所有期間、再開時の入力ハッシュを境界で検査します。

SOLID/KISS/DRYの適用範囲は以上の責務・差替え・重複排除です。形式的な全設計証明、万能なロボット形式対応、外部リンターの合格を主張するものではありません。今回は数値・合成回復・FK・画像・記録・再現のテストとコード読解を実施しています。
